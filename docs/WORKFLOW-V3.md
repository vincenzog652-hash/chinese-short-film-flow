# Workflow V3 — Lean Content และ Evidence Gate

เอกสารนี้นำแนวคิดที่มีประโยชน์จาก Ponytail, Everything Claude Code (ECC) และ Superpowers มาปรับให้เหมาะกับการผลิตหนังสั้น ไม่ได้ติดตั้งหรือคัดลอกเครื่องมือเหล่านั้นทั้งชุด

## หลักการ 3 ชั้น

### 1. LEAN_SCOPE — ทำเท่าที่จำเป็น

ใช้แนวคิดงานกระชับเพื่อลดการเจนซ้ำ โดยไม่ลดทอนแกนเรื่อง

- ระบุ deliverable ที่ต้องได้ในรอบปัจจุบัน
- แยก `must-have` ออกจาก `nice-to-have`
- สร้างหนึ่งผลลัพธ์ต่อการตัดสินใจเมื่อเพียงพอ
- ล็อกชิ้นที่ผู้ใช้อนุมัติแล้ว ห้ามสร้างใหม่โดยไม่มีเหตุผล
- ตั้งเพดาน take และเครดิตก่อนสร้างสื่อ
- ห้ามตัด continuity, disclosure หรือขั้นตรวจเพียงเพื่อให้งานสั้นลง

### 2. CONTENT_PLAN — Hook ถึง Caption

วางโครงคอนเทนต์ก่อนผลิต เพื่อให้แต่ละช็อตมีหน้าที่ชัดเจน

| ส่วน | คำถามที่ต้องตอบ |
|---|---|
| Hook | 1–3 วินาทีแรกทำให้หยุดดูเพราะอะไร |
| Conflict | ใครต้องการอะไร และอะไรขวางอยู่ |
| Reveal | ข้อมูลใหม่เปลี่ยนความเข้าใจตรงไหน |
| Cliffhanger | ตอนจบเปิดคำถามอะไรต่อ |
| Caption | ประโยคเปิดสอดคล้องกับสิ่งที่เห็นจริงหรือไม่ |
| CTA | ต้องการให้ดูตอนต่อ แสดงความคิดเห็น หรือบันทึกโพสต์ |

Caption และ CTA เป็นร่างจนกว่าจะมีไฟล์ final ที่ตรวจแล้ว ห้ามอ้างเหตุการณ์หรือคุณภาพที่ไม่ปรากฏในผลงานจริง

### 3. EVIDENCE_GATE — ตรวจหลักฐานก่อนรายงานว่าเสร็จ

สถานะ `ACCEPTED`, `EXPORTED` และ `PUBLISHED` ต้องมีหลักฐานตามตาราง

| สถานะ | หลักฐานขั้นต่ำ |
|---|---|
| ACCEPTED | เปิดไฟล์ take ที่เลือกได้ ตรวจภาพและเสียงตาม QC พร้อมชื่อผู้ตรวจ |
| EXPORTED | เปิดไฟล์ final ได้ มี duration, aspect ratio, resolution และชื่อไฟล์ |
| PUBLISHED | เปิดโพสต์จริงได้ มีบัญชีปลายทาง เวลา และ URL |
| NEEDS_HUMAN_REVIEW | ระบุสิ่งที่ระบบตรวจไม่ได้และผู้ใช้ต้องตรวจเอง |

คำว่า `completed` จากระบบสร้างสื่อหมายถึงงานประมวลผลจบเท่านั้น ไม่เท่ากับ QC ผ่าน

## ลำดับ V3

`Brief → Lean Scope → Hook/Story → Character Lock → Opening Frames → Shot Test → Remaining Shots → Evidence Gate → Caption/CTA → Export/Publish`

## Stop conditions

หยุดและรายงาน `BLOCKED` เมื่อเกิดข้อใดข้อหนึ่ง:

- ไม่พบไฟล์หรือ reference ที่พรอมป์ต์อ้างถึง
- ไม่ทราบต้นทุนต่อผลลัพธ์หรือเกินงบที่อนุญาต
- ผู้ใช้ยังไม่อนุมัติตัวละครหรือองค์ประกอบที่ต้องล็อก
- ผลลัพธ์สองครั้งติดล้มด้วยสาเหตุเดิมและไม่มีสมมติฐานใหม่
- ไม่มีเครื่องมือดูหรือฟัง แต่ขั้นนั้นต้องอาศัยการตรวจภาพหรือเสียง
- ไม่มีคำสั่งเผยแพร่หรือไม่ยืนยันบัญชีปลายทาง

## Completion report

เมื่อจบรอบ ให้รายงานเพียง:

1. **เสร็จแล้ว:** สิ่งที่สร้างและตรวจจริง
2. **หลักฐาน:** ชื่อไฟล์, take, QC หรือ URL ที่เปิดตรวจได้
3. **ยังไม่ผ่าน:** ปัญหาหรือ `NEEDS_HUMAN_REVIEW`
4. **ขั้นถัดไป:** การกระทำเดียวที่เหมาะสมที่สุด

ห้ามใช้ถ้อยคำว่า “เสร็จสมบูรณ์” หากยังมีรายการตรวจที่ไม่ผ่านหรือไม่มีหลักฐานรองรับ
